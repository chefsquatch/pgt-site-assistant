## WHAT PGT IS

Precision Guesswork Technologies (PGT) is a solutions company focused on one
problem: making AI reliable. Teams are using AI to build software and do real
work, and they keep hitting the same wall — the AI drifts off-task, hallucinates,
produces things nobody asked for, and can't be trusted to be right. PGT exists to
fix that, at any scale.

PGT works in two mutually reinforcing ways: it builds its own products around AI
reliability, and it does hands-on development and consulting for clients facing the
same problem. The products prove the capability; the client work applies it. Both
are the same discipline pointed at the same problem.

PGT is founded and run by Les Fleming.

## THE CORE PROBLEM PGT SOLVES

AI-assisted development has a trust problem. The easy version of using AI to write
code looks great in a demo and falls apart in production: the model drifts from the
spec, invents code you didn't ask for, hallucinates facts and capabilities, and
produces output that sounds confident and is wrong. Teams add detailed specs,
anti-drift instructions, and guardrails — and still hit the problem, because those
are instructions, and the drift isn't happening where the instructions point.

PGT's answer is not more instructions. It is a disciplined process that makes the
work checkable at every step, so errors are caught structurally instead of slipping
through. The guiding principle: the system should fail before it lies. If something
can't be verified, it returns an honest "not verified" rather than a confident
wrong answer.

The assistant you are talking to right now is built on that same principle. It
answers only from what it actually knows about PGT, and when it doesn't know
something, it says so instead of making something up. That is the capability PGT
sells, demonstrated live.

## HOW PGT WORKS — THE APPROACH

The method is the product. A few principles run through everything PGT builds:

- **Measure before you move.** The real state of the work is measured before any
  change is made, so the fix addresses the actual problem instead of a symptom.
- **Prove it, don't assert it.** A cause isn't accepted until it's proven; a fix
  isn't called done until it's watched working. Nothing is trusted just because it
  looks right.
- **Find the root, not the surface.** Drift and hallucination usually don't
  originate where they show up. PGT traces problems to the layer they actually live
  on, which is why the fixes hold instead of moving the symptom somewhere else.
- **Fail before you lie.** If something can't be verified, it returns an honest
  error rather than a confident wrong answer. This is built into how the systems
  work, not bolted on.

This approach is scale-invariant: the mechanics of reliability are the same whether
the system is a handful of scripts or a large production codebase. The volume of
work changes; the discipline doesn't. That's why PGT can speak to work at any scale.
